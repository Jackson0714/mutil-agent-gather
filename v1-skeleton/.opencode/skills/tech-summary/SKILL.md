# 技术内容深度分析技能

## 使用场景

当需要对采集的技术内容进行深度分析总结时使用此技能。通过对原始数据的结构化分析，提取技术亮点、评估价值、发现趋势，帮助快速筛选和理解高质量技术内容。

## 执行步骤

1. **读取原始数据**：读取 `knowledge/raw/` 目录下最新采集的文件（如 `github-trending-YYYY-MM-DD.json` 或 `hacker-news-YYYY-MM-DD.json`）
2. **逐条深度分析**：对每条内容进行结构化分析，包含四个维度：
   - **摘要**：不超过 50 字，概括核心内容
   - **技术亮点**：列出 2-3 个用事实说话的关键亮点
   - **评分**：1-10 分，附上评分理由
   - **标签建议**：推荐合适的分类标签
3. **趋势发现**：分析多条内容，发现共同主题、新概念或技术趋势
4. **输出分析结果**：将分析结果按指定 JSON 结构输出

## 评分标准

| 评分 | 等级 | 说明 |
|------|------|------|
| 9-10 | 改变格局 | 突破性技术或创新，有望重塑行业格局 |
| 7-8 | 直接有帮助 | 实用性强的工具/框架，解决实际问题 |
| 5-6 | 值得了解 | 有趣的尝试，值得关注但非必需 |
| 1-4 | 可略过 | 常规更新或价值有限 |

## 注意事项

- 每批分析不超过 15 个项目
- 9-10 分的高分项目每批不超过 2 个，保持稀缺性
- 技术亮点需基于事实，避免主观臆测
- 标签需与项目实际内容匹配，控制在 3-5 个

## 输出格式

```json
{
  "source": "tech_summary",
  "skill": "tech-summary",
  "analyzed_at": "2026-06-03T12:00:00Z",
  "trends": ["共同主题1", "新概念2"],
  "items": [
    {
      "name": "project-name",
      "summary": "不超过50字的摘要",
      "highlights": ["亮点1", "亮点2", "亮点3"],
      "score": 8,
      "reason": "评分理由说明",
      "tags": ["tag1", "tag2", "tag3"]
    }
  ]
}
```
